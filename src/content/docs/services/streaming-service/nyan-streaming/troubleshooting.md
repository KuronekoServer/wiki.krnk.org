# トラブルシューティング

まず、ダッシュボードのストリームキー一覧とキー詳細を開き、キーの状態、入力ビットレート、選択中のノード／リージョン、制限バナーを確認してください。

## 症状から確認する

| 症状                          | 最初に確認すること                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| 配信を開始できない            | RTMP URL と配信用シークレット、ノードの稼働状態、キーの制限バナー                           |
| 映像が出ない                  | 映像コーデックが H.264 (AVC) か                                                             |
| 音声が出ない                  | 音声コーデックが AAC か。LPCM 配信は RTSP のみで、RTSP 以外の視聴音声は AAC                 |
| RTSP 配信を開始できない       | プロバイダーがポート 554 または RTSP 通信を制限していないか                                 |
| ブラウザで HLS を再生できない | URL が `.m3u8` か、Safari 以外では hls.js 対応プレイヤーを利用しているか                    |
| VRChat で再生できない         | AVPro 対応プレイヤーか、RTSP / RTSPT URL を使っているか、Stream Mode / Low Latency が有効か |
| 遅延が大きい                  | HLS ではなく RTSP または WebRTC (WHEP) を利用できるか                                       |
| 配信が途中で切れた            | ビットレート、24時間連続配信、規約違反の制限バナーや通知                                    |

## RTSP 配信だけ開始できない

一部のインターネットサービスプロバイダー（ISP）は、ポート 554 や RTSP 通信を制限しています。その回線で RTMP や WebRTC は配信できる一方、RTSP だけ接続できない場合は、**プロバイダー側の通信制限が原因であり、Nyan Streaming の障害ではありません**。

契約中のプロバイダーへ RTSP 通信の利用可否をお問い合わせいただくか、別の回線をお試しください。RTSP を利用できない場合は、音声を AAC に変更して RTMP または WebRTC で配信してください。

## 制限画面が表示された

ビットレート、24時間連続配信、利用規約違反で配信が停止されると、通常の配信内容の代わりに理由別の警告画面が視聴者へ表示されます。ダッシュボードのキー一覧には理由が表示され、自動解除される制限には解除予定時刻も表示されます。

:::note
警告画面とメール・Webhook・アプリ内通知の言語は、組織の **設定 → 一般 → デフォルト言語**で決まります。日本語を選ぶと日本語、それ以外は英語で表示されます。
:::

### 24時間以上の連続配信

24時間制限が有効なノードで、同じ publish セッションが24時間連続した場合に適用されます。対象配信を停止し、**組織の全ストリームキーを1日間**ブロックします。再接続すると連続時間は新しいセッションとして数え直されます。**Node03はこの制限の対象外**です。

![24時間以上の連続配信による制限画面（日本語）](https://cdn.krnk.org/kuronekoserver/nyst/warning/24h-jp.png)

**対処方法**

1. ダッシュボードで解除予定時刻を確認します。
2. 解除までは配信を再開できません。
3. 解除後に新しいセッションとして配信を開始します。
4. 低ビットレートで24時間を超える継続配信にはNode03を使用します。それ以外の条件で長時間運用が必要な場合は、事前に[お問い合わせ](https://krnk.org/contact/)ください。

### 入力ビットレート上限の超過

組織内で同時配信している全ストリームの入力ビットレート合計がプラン上限を**10分以上**超え続けた場合に適用されます。合計が上限以下になるまで新しく開始された配信から停止され、停止対象のキーは**1時間**再配信できません。

![入力ビットレート上限の超過による制限画面（日本語）](https://cdn.krnk.org/kuronekoserver/nyst/warning/bitrate-jp.png)

**対処方法**

1. 同時配信しているすべてのエンコーダの映像・音声ビットレートを合計します。
2. 各配信のビットレートを下げるか、不要な同時配信を終了し、組織合計を上限以内にします。
3. ダッシュボードで停止対象キーの解除予定時刻を確認します。
4. 解除後に再接続します。より高い上限が必要な場合は、プラン変更またはビットレート追加を申請します。

### その他の利用規約違反

管理者が利用規約違反を確認した場合、対象組織またはユーザーの配信が停止・ブロックされます。この制限に自動解除時刻はありません。

![利用規約違反による制限画面（日本語）](https://cdn.krnk.org/kuronekoserver/nyst/warning/tos-jp.png?t=1787304185303)

**対処方法**

1. [Nyan Streaming 利用規約](https://krnk.org/terms/nyan-streaming)と通知に記載された条項を確認します。
2. 該当する配信内容を停止・修正します。
3. 解除の審査は[お問い合わせ](https://krnk.org/contact/)ください。

## その他の上限

### 同時視聴者数

組織全体の同時視聴者数がプラン上限に達すると、新しい視聴者の接続が拒否されます。すでに視聴中の接続は継続します。上限を空けるか、プラン／視聴者アドオンを変更してください。

### ストレージ容量

組織のストレージ上限に達すると、録画は自動停止します。配信自体は継続し、停止時点までの録画はアップロードされます。不要なアーカイブやメディアを削除するか、容量を追加してください。

### 地域制限

日本国内限定のノード／プランでは、対象地域外から視聴できません。配信キーのプラン、選択中のノード、リージョンを確認してください。

## お問い合わせ時に添える情報

- 組織名とストリームキーの**表示名**（配信用シークレットは送らないでください）
- 発生時刻とタイムゾーン
- 利用したノード／リージョンとプロトコル（RTMP / RTSP / HLS / WebRTC）
- ダッシュボードに表示されたエラーまたは制限理由
- OBS の統計・ログを添える場合は、配信用シークレットや個人情報を削除したもの
